# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) once published.

## [Unreleased]

### Changed

- **The repository moved to `tvstore/Forgebase` and is public** (owner decision of 2026-10-31, *"repo sudah saya ganti public"*; [owner decisions](docs/owner-decisions.md#repository-public-2026-10-31-information-session)). Repository URLs in `Cargo.toml`, the new-app templates, the README and the docs point to the new location, and the licence wording says the project is open source under the MIT licence (AGENTS.md section 2, README, vision). The project pause of 2026-10-30 is cancelled. No code behaviour changes.
- **CI cost** (owner decision of 2026-10-30, "setuju C-1 sampai C-5"; [maintenance policy](docs/blueprint/maintenance-policy.md#ci)). CI runs on non-draft pull requests, weekly and on demand, no longer on push to main or daily. A `changes` job classifies the changed paths (`.github/ci/classify-paths.py`, with a unit test) so that documentation-only, desk-only and Rust-only changes run only the jobs they need; a new `docs` job checks relative links and anchors offline (`.github/ci/linkcheck.py`). The Cargo registry, git db and `target/` (and the cargo-deny binary and the npm cache) are cached with `actions/cache` (GitHub-owned, pinned by SHA), `CARGO_INCREMENTAL=0` is set, and the `msrv` and `deny` jobs are one job, `msrv-deny`. [AGENTS.md section 10.2](AGENTS.md#102-roles-in-the-working-session) gains the draft-pull-request process.

### Added

- **M9.0: TLS to PostgreSQL, the Render + Neon path and the CI job `ci-result`** (owner decision of 2026-10-31, *"setuju ci-result dan setuju M9.0"*; [ADR 0018](docs/adr/0018-postgres-tls.md); [owner decisions](docs/owner-decisions.md#postgres-tls-and-ci-result-2026-10-31-setuju-ci-result-dan-setuju-m90-information-session)). **New dependency `tokio-postgres-rustls` 0.14.0 (MIT)**, with `rustls` and `rustls-native-certs` as direct dependencies of `forgebase-db`; rustls runs on `ring`, and `aws-lc-rs`, OpenSSL and `webpki-roots` are not in the tree ([dependency evaluation](docs/blueprint/dependency-evaluation.md#13-tls-to-postgresql-m90)). Every connection now honours `sslmode` in the database URL: none or `disable` means no TLS (as before); `require`, `verify-ca` and `verify-full` mean TLS with full verification (chain and host name); `prefer`, `allow`, other values, `sslcert`, `sslkey` and the other `ssl*` options are refused with a clear error; `sslrootcert=<path>` trusts only that PEM file and `sslrootcert=system` (or nothing) the operating system's roots. It covers the pool, `migrate`, `site create`, `site backup` and `site restore` (the tools get `PGSSLMODE=verify-full` and `PGSSLROOTCERT`), and per-site URLs. New error variant `DbError::Tls`. Tests against a PostgreSQL 16 with TLS and a throwaway CA (`.github/ci/pg-tls.sh`, in the CI job `check` and locally: [CONTRIBUTING](CONTRIBUTING.md#postgresql-for-tests)). The deploy guide has a Render + Neon free path (no new bootstrap feature: `user create` runs locally against the Neon URL), the operations guide documents `sslmode` and `sslrootcert`. CI: the job **`ci-result`** (`if: always()`, needs every other job, fails on `failure` or `cancelled`, skipped is fine) is the one check the owner's ruleset on `main` requires ([maintenance policy](docs/blueprint/maintenance-policy.md#ci)). The ADRs of the rest of M9 shift by one (methods 0019, webhooks 0020). **Behaviour change:** `site backup` and `site restore` used to pass no `PGSSLMODE` unless the URL had one and so ran with libpq's `prefer`; they now pass `PGSSLMODE=disable` when the URL has no TLS; and a URL with `sslmode=prefer` is refused everywhere.

- **M7.3: `site backup`, `site restore`, `site create --empty`, the operations guide and the CI job `sites`; M7 is Done** ([ADR 0014](docs/adr/0014-multi-site-database-per-site.md#implementation-details-m73), owner decision M7-6; no new crate dependency; the public API of the `forgebase` crate is unchanged). `forgebase site backup NAME --out FILE` runs `pg_dump --format=custom --no-owner --no-privileges` on the site's database; `forgebase site restore NAME --from FILE` runs `pg_restore --no-owner --no-privileges --exit-on-error --single-transaction` into a database that exists and is **empty** (a conservative SQL check, `forgebase_db::EMPTY_CHECK_SQL`), and never migrates by itself; `site create NAME --empty` creates the database without migrating it. `pg_dump` and `pg_restore` are external tools (`PATH` or `FORGEBASE_PG_BIN`, not bundled) of the server's major version (a newer `pg_dump` writes an archive the server's `pg_restore` may not read, and a newer `pg_restore` sends SQL an older server rejects), and for a restore the dump must not be newer than the server (an upgrade is allowed); otherwise the versions are named in the refusal. The database URL and password reach them only as `PG*` environment variables (never on a command line or in a message; other inherited `PG*` variables are removed; a URL option that cannot be expressed is an error that names the option). A backup never overwrites a file (no `--force`), is created with mode 0600, is written to `FILE.partial` and published under its name only when complete: a failure removes it, and an interrupted backup (SIGINT, SIGTERM) can leave only `FILE.partial`, never a partial `FILE`. `forgebase-db`: `pg_environment`, `inspect_database`, `DatabaseInfo`, `EMPTY_CHECK_SQL`, `DbError::Backup` (internal crate). A `[[sites]]` entry takes an optional `apps = [...]`: a subset of the binary's apps, closed under `depends_on` (dependencies are never added automatically; an unknown app, a duplicate and a missing dependency are config errors naming the site; an empty list is allowed; absent means all apps). Removing an app from a site keeps its tables and data: `migrate` warns once per such app on standard error, exit 0, and its queued jobs stay queued. `forgebase site list` (name, hosts, apps, the name of the database variable; no database, never the URL) and `forgebase site create NAME` (`CREATE DATABASE` through the maintenance database `postgres`, `--maintenance-db NAME` to change it; refuses an existing database with exit 1; then migrates; needs the `CREATEDB` privilege). `forgebase-db`: `create_database`, `recorded_apps` (internal crate). - **M7.1: sites, the config file and the site context everywhere** ([ADR 0014](docs/adr/0014-multi-site-database-per-site.md), owner decisions M7-1 to M7-7 of the M7 plan; M7 is In progress, M7.2 and M7.3 are next; no new crate dependency). - `forgebase_db::MigrateReport` has the new field `app_migrations`; `forgebase_db::migrate` holds the migration advisory lock for the whole call (a session-level lock on a connection that is taken out of the pool and closed at the end, so it cannot leak into the pool).
