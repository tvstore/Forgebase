# 0017 Desk styling: Tailwind CSS, theme tokens, no component kits

- Status: Accepted (owner decisions T1 to T4 of the plan "UX.3 Desk restyle with Tailwind CSS", 2026-10-30). Supersedes owner decision UX-5 (the yellow accent) of UX.2.
- Date: 2026-10-30
- Amended by the section "UX.4 (2026-10-30)" at the end (owner decisions U1 to U7; the Accepted text above is not rewritten).

## Context

UX.2 (PR #26) gave the desk a layout, components and one hand-written stylesheet (`desk/src/styles.css`, about 1,000 lines of plain CSS with custom properties), and the Forgebase yellow as its only accent. The owner asked for a UI that is clean, simple, elegant and suited to corporate use, built with Tailwind, with no yellow and with the background colour of the logo banner (navy `#1B2A5C`, `docs/assets/logo-banner.svg`). The desk's other constraints do not change: no UI component library (M4 decision 1), only `react` and `react-dom` at runtime, a Content-Security-Policy that forbids inline script and style, and a build that needs no network.

## Decision

The decisions below are the owner's.

- **T1. Tailwind CSS v4 as a build-time tool.** `tailwindcss` and `@tailwindcss/vite`, both exact `4.3.3` (MIT), are **development dependencies**: Vite compiles `desk/src/styles.css` into the one static CSS file that the desk already ships under `assets/`. Nothing of Tailwind runs in the browser. Still **no UI component library** and no Tailwind plugin (no typography, forms or container-query plugin, no Tailwind UI, daisyUI, Headless UI or shadcn), and no icon set.
- **T2. A corporate palette.** The primary colour is navy `#1B2A5C`, with a darker hover and two light tints for selected rows and the active sidebar item. Neutrals are slate greys on a light page background. **Yellow stays only inside the logo mark** and is never a UI accent. This supersedes UX-5.
- **T3. The system font stack.** No web font, so no external request (CSP).
- **T4. UX.3 comes before M8.1.** The M8 desk work uses this theme.

How it is built (implementation, not a decision): the tokens are in the `@theme` block of `desk/src/styles.css`; the existing semantic class names are kept and defined in `@layer components` with `@apply` and the tokens, so the TSX keeps its class names (only `Badge` and `TableGrid` changed slightly) and behaviour stays the same; new desk work (M8) may use utility classes directly where that reads better. There is one style system, not two. Class names that are chosen at run time are full literal strings (`Badge`), because Tailwind finds classes by scanning the source. Contrast ratios are recorded in [architecture, section 11](../blueprint/architecture.md#11-desk-reports-workflow).

## Alternatives considered

- **Keep the hand-written CSS and only change the colours.** The cheapest change, and what the plan weighed first. Not chosen: the owner decided on Tailwind (T1) for a consistent scale and for a styling vocabulary that new desk work in M8 can follow without growing a private one.
- **A component library or a Tailwind plugin kit.** Rejected (M4 decision 1): every runtime dependency is a maintenance cost, and the desk has a small, fixed set of components.
- **Tailwind through the CDN script or the CLI standalone binary.** Rejected: the CDN is a runtime dependency and an external request (CSP); the standalone binary is a download outside npm that the licence and audit checks do not see.

## Consequences

- **One more development toolchain to maintain.** Upgrades of `tailwindcss` and `@tailwindcss/vite` are pinned and go through review with before and after screenshots ([maintenance policy](../blueprint/maintenance-policy.md)).
- **Dependency cost:** 33 more packages in the lockfile, all development only and all MIT, ISC or MPL-2.0 (the allow-list is unchanged); details in [dependency evaluation, section 12](../blueprint/dependency-evaluation.md#12-frontend). `@tailwindcss/oxide` is a native binary, chosen by npm from its optional platform packages; `desk/.npmrc` still sets `ignore-scripts=true` and no install script is needed.
- **The CSP is unchanged.** The built `index.html` has no inline script or style, and the CSS has no `@import` and no `url(...)`.
- **The shipped CSS is generated.** Review the source (`styles.css` and the components), not `dist/`. The CSS may use modern features (`color-mix`, cascade layers), which the supported browsers have.
- The yellow of UX.2 is gone from the UI; the logo mark keeps it. Checks for that: a search of the sources for the two yellow values finds only `Logo.tsx` and the logo asset.

## UX.4 (2026-10-30)

Amendment. The owner asked, after UX.3: *"apa bisa ui dibuat lebih smoothy agar terkesan elegan high kualitas, seperti frappe? tapi tetap pakai warna dasar yang sama"* and approved the plan with *"setuju semua rencana mu"*. The base colours stay (navy `#1B2A5C` is the primary, yellow only in the logo mark: T2 holds). The decisions below are the owner's; they extend T1 to T4 and change two of the statements above, which are named. Frappe is a visual and behavioural reference only: no Frappe code or asset is copied.

- **U1. UX.4 runs between M8.1 and M8.2**, so that every M8 desk screen is built in the polished style.
- **U2. Inter, self-hosted.** `@fontsource-variable/inter` (exact `5.3.0`, **OFL-1.1**) is a **runtime dependency of the desk that ships fonts and no JavaScript**: one `@font-face` for the **Latin** variable `woff2` (48 KB) with `font-display: swap`, referenced from the stylesheet by a relative `url(...)`; Vite emits the file to `assets/`, which `forgebase serve` already serves as `font/woff2` from `'self'`. The package's default CSS (every subset) is not imported. The system font stack stays as the fallback. **This replaces T3** ("the system font stack, no web font") and the statement that the CSS has "no `url(...)`": the one `url(...)` is that font. The CSP is unchanged (`font-src 'self'` was already there; no inline style or script, no remote URL). The **OFL-1.1 licence is allowed for fonts only**: `desk/scripts/check-licenses.mjs` accepts it for the `@fontsource` and `@fontsource-variable` package scopes and nowhere else, and lists the font as the third runtime dependency next to `react` and `react-dom`.
- **U3. A curated set of Lucide icons copied into the repository.** 34 SVG icons (UI icons and DocType icons) from `lucide-static` 1.65.0 (ISC; the Feather-derived icons also carry the MIT notice) are written as small inline React components in `desk/src/icons.tsx`, with the licence text in `desk/src/icons/LICENSE-lucide.txt`. **They are copied, not a dependency**: `lucide`, `lucide-react` and `lucide-static` are not in `package.json` or the lockfile. This replaces the "no icon set" of T1 (no icon *library*; a copied, curated set is allowed). DocTypes may name an icon with an optional `icon = "file-text"` key; the allowed names are **one list**, `crates/forgebase-core/src/doctype_icons.txt` (an unknown name is a load error that lists them; not allowed on a child DocType), and a desk test checks that `icons.tsx` has a component for exactly those names, so the two cannot drift. The metadata API returns `icon` (`null` when absent) and the desk uses `file-text` then.
- **U4. The look and the motion.** Tokens in `@theme` (page `#F7F8FA`, white cards with a hairline `#EBEDF0` and a soft shadow, a 12 px card radius and 8 px control radius, filled grey inputs `#F3F4F6` with a navy focus ring, navy-700 `#142046` for hover and navy-50 `#EEF1F8` for selection, pill badges with a 6 px status dot, 13.5 px Inter with tabular numbers in tables, a 48 px top bar, a 224 px sidebar, a sticky page header) and **150 to 200 ms CSS-only motion** (hover and focus colours, menus, dialogs fading and scaling in, the toast sliding in, a short page fade, the skeleton shimmer). There is no animation library, so the CSP is unchanged. `@media (prefers-reduced-motion: reduce)` switches off **every** transition and animation with one rule at the end of `styles.css`; a Playwright test emulates it and asserts that a dialog's computed `animation-duration` and `transition-duration` are `0s`. Colours that failed AA for text were darkened and are recorded in the table in [architecture, section 11](../blueprint/architecture.md#11-desk-reports-workflow) (the muted text `#7C838F` of the mockup, 3.8:1 on white, is `#5E6572`, 5.9:1; the border of filled controls is `#7A828F`, which reaches 3:1 on the grey fill).
- **U5, U6, U7** are features, not styling decisions, and are recorded in [architecture, sections 7 and 11](../blueprint/architecture.md#11-desk-reports-workflow): **U5** the command bar (Ctrl/Cmd+K), navigation only, on the client, no new API and no storage; **U6** the form in cards with a right-hand info panel; **U7** link titles, a permission-aware addition to the list and read routes (`?link_titles=1`).

**Consequences.** One new runtime package (a font; CSS and `woff2` only, no JavaScript in the bundle: the first-load JavaScript is unchanged in kind), one new copied-in asset set with its licence notice, one licence (OFL-1.1) allowed for fonts only, and no new Rust crate. First-load size (CSS, JS and the font) is about 142 KB gzip, under the 300 KB budget (measured, in architecture section 11). Upgrading the font is a version bump of one package; the icons are never upgraded automatically (a new icon is copied by hand with its notice). The yellow check of T2 still holds: the two yellow values appear only in `Logo.tsx` and the logo asset.

**Licence notices (owner decision of 2026-10-30, *"setujui rekomendasi putusanmu"*).** The built desk ships `THIRD-PARTY-LICENSES.txt` in `desk/dist/`: Inter's OFL-1.1 text (verbatim from the package, version named in the header) and the Lucide notice. The source is `desk/public/THIRD-PARTY-LICENSES.txt`, which Vite copies to `dist/` as it is; `desk/src/licenses.test.ts` fails when it differs from the installed font package's `LICENSE` or from `desk/src/icons/LICENSE-lucide.txt`, so an upgrade cannot leave it stale. The file is part of the artefact but is not served over HTTP (`forgebase serve` serves only `index.html` and `assets/{name}`; no Rust change was made). Details: [maintenance policy](../blueprint/maintenance-policy.md), [dependency evaluation, section 12](../blueprint/dependency-evaluation.md#12-frontend).
