# examples/sites

Two sites on one server, a backup restored into a new database ([ADR 0014](../../docs/adr/0014-multi-site-database-per-site.md), M7.3), (M9.5) a webhook delivered to a test receiver, and (M10.4) a site custom field and a restricted Sales User. It uses the composed binary of [`sales_extension`](../sales_extension/README.md).

- [`forgebase.toml`](forgebase.toml): the site `shop` (the `sales` app only), the site `field` (every app) and `restore_check` (the target of the restore).
- [`ci.sh`](ci.sh): creates the sites, serves them, checks that each answers for its own host with its own users and apps (and that an unknown host is 404), then backs up `shop`, restores it into `restore_check` and compares the documents. The script then proves, on `shop` unless a bullet names another site:
  - the approval workflow and a shared saved view over HTTP (M8.5);
  - the fixture of the sales app (M9.4): the first `migrate` kept the two customer groups the SQL migration made and inserted `Online`, and a second `migrate` finds the three unchanged;
  - **a webhook** (M9.5, [ADR 0020](../../docs/adr/0020-outgoing-webhooks.md)): it adds a webhook on `sales_order` for `submit`, approves an order, runs the worker until the delivery arrives (at most 30 seconds) and checks that the receiver recorded exactly one verified `submit` delivery of that order. It also checks that a forged signature is refused and that `webhook test` exits 0.
  - **a site custom field** (M10.1, [ADR 0023](../../docs/adr/0023-metadata-overlays.md)): with the server running, `customize field add --site field --doctype customer --field -` (the definition on standard input) adds `custom_region`. The script waits at most 15 seconds (the server checks every 10) until the metadata of `field` lists it, checks that `shop` does not, writes a value through the API and reads it back, then `customize field disable` hides it from the metadata and the document (and input for it is refused) while `enable` brings the stored value back (the column and data were kept);
  - **user permissions** (M10.3, [ADR 0025](../../docs/adr/0025-user-permissions.md)): `user permission add --user bob --doctype customer_group --value Retail` restricts the Sales User to one group. As bob the customer list has the Retail and the no-group customers and not the Wholesale one (a get by name is 404), the group list has `Retail` only, and the metadata of `customer_group` offers no create (also to a Sales Manager restricted the same way, who gets `403` on create). `user permission list` shows the row, and after `remove` the Wholesale customer is visible on the next request. The walkthrough is in [Customizing and restricting data](../../docs/guide/customizing.md).
- [`receiver.py`](receiver.py): the test receiver, Python standard library only. It verifies the signature with the recipe of the [webhooks guide](../../docs/guide/webhooks.md#verifying-a-delivery) and records the verified deliveries in a file. The script starts it on `127.0.0.1` and stops it by its PID. The secret is generated by the script, handed over by the environment and standard input, and never printed.

The `sites` job of CI runs the script.

## Run it locally

You need PostgreSQL 16 with a role that has `CREATEDB`, the PostgreSQL client tools (`pg_dump` and `pg_restore`, of the server's major version, 16; set `FORGEBASE_PG_BIN` to their directory if another version is first on `PATH`), `curl`, `jq` and `python3`. The three databases are created by the script and must not exist.

```sh
cargo build --locked -p sales_extension
export SHOP_DATABASE_URL=postgres://user:password@localhost:5432/fb_sites_shop
export FIELD_DATABASE_URL=postgres://user:password@localhost:5432/fb_sites_field
export RESTORE_DATABASE_URL=postgres://user:password@localhost:5432/fb_sites_restore
examples/sites/ci.sh
```

The script never prints a URL. It leaves the three databases in place: drop them when you are done (`DROP DATABASE fb_sites_shop WITH (FORCE)`, and the same for `fb_sites_field` and `fb_sites_restore`). `SITES_PORT` changes the port (default 8000), `RECEIVER_PORT` the port of the webhook receiver (default 8001); `FORGEBASE_BIN` the binary.

The webhook is added with `--allow-private` and `--insecure-http` because the receiver is on `127.0.0.1` and speaks plain HTTP. **These flags are for local development and tests only**; a production webhook is `https://` to a public address.

The commands it runs are the ones of the [operations guide](../../docs/guide/operations.md).
